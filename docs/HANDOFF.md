- 同号幂等不等于跨群/跨SKU活动去重。文本指纹仅助审；多商品文案不能用最低数字代替整单价格。
- 返卡/返款、凑单进入hold；虚拟补差、工业小件exclude，瑕疵hold。review也未通过真实性核验，不自动发布。
- 目录复查中，已公开项报价变化或无法再确认时暂停指引，明确“不代表活动结束”；网络/格式失败不按商品缺失处理。重新出现不自动恢复，不自动延长展示截止。
- 发布与版本/通知依赖数据库事务和约束；购物已验证还须填写另购最低支出及无需交付已有资产的依据。未知不能填0。

## 下一步与剩余验收
1. 核实购物候选的最低SKU/数量、运费和实际资格；登录内报价只由自愿用户在自己设备提供脱敏证据，不索取Cookie、验证码，不自动购买。当前#6仍未实领。
2. 用 deploy/source-report.sql 分开记录基线、人工、partial新增与有效产出。供应方样本首见窗口不是品牌首发延迟，不能把采集条数当羊毛产量。第7/14天按既定质量门槛复盘，不降标准。
3. 真实手机推送待验：本次设备数0；/devices/ 的受理不等于可见。普通内测账号使用 create-tester.sh（先由运营方核实邮箱归属）。iPhone从主屏幕Web App操作。具体证据口径见TRUST_AND_PUSH。
4. AI只做摘录；购物样本无可评分输出，准确率不可计算。需供应侧状态/权限/限额恢复后再试单条，不换付费模型或借用key。
5. 公开注册、真实邮件、管理员后台安全放行、站外告警、异机加密备份及恢复后账号撤销对账尚未验收。不是正式公众运营完成。
