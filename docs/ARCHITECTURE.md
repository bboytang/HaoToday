# 架构与启动
Django 模块化单体、服务端模板、PostgreSQL；应用与 worker 独立运行，一个数据库，不引入 Redis/Kubernetes。邀请内测的采集与推送任务由 systemd 定时在应用容器内启动；数据库事务触发器记录版本并派发匹配的站内消息。
数据流：来源 → 运行与观察 → 活动版本及证据 → 发布事件 → 用户消息与设备投递。观察持久化后才推进水位。采用事务、唯一键和任务租约支持故障重跑。
本机：python3 -m venv .venv，再运行 .venv/bin/pip install -r requirements.txt。scripts/check.sh 需要 Docker，自动启动一次性 PostgreSQL 17 并在退出时停止，不接触现网库。
开发启动：创建专用 PostgreSQL 用户和数据库；根据 .env.example 填写 .env（密钥可用 openssl rand -hex 32 生成），set -a; source .env; set +a，然后 .venv/bin/python manage.py migrate 及 .venv/bin/python manage.py runserver 127.0.0.1:8000。用 /health/ 检查数据库可用性。
上线不得用 runserver。独立低权限进程与私有数据库，复用反代 HTTPS；部署前复核现有服务，禁任意 URL 抓取、转义外部内容，后台 MFA、日志脱敏、每日加密异机备份，恢复演练目标 RPO 24 小时/RTO 4 小时。上线前核查备案适用性、隐私告知、投诉注销和来源权利。单源、推送、注册均需独立开关。此处是上线门槛，非上线成绩。

## 已有服务器、AI 和手机时，怎样算实际成本
内测不要求另买服务器或 AI 套餐。区分已付固定成本（服务器、域名、已有模型套餐）与因为本项目新增的支出；分摊固定成本要单列，不是又付了一遍。新增用量可能涉及超套餐流量、AI、邮件、异机备份，选付费来源须先单独批准。本轮资源测量不含任何购买行为。
- 从仓库运行 `ssh -T root@43.143.230.174 'bash -s' < deploy/resource-report.sh`；只读本项目容器和数据库。CPU、内存是瞬时值，主机可用空间与其他服务共享；网络计数从各容器创建时开始，含内部通信，不能相加当公网账单。记录采集和推送任务运行时段另做峰值取样。
- AI 的 24 小时 token 仅来自成功持久化的去重摘录。失败、未缓存和评测回滚可能有用量，不能用这列当账单。用供应商控制台按项目/时间对账；共用套餐无法区分时报告“不可归因”，不要擅自换 Key。未配置邮件/异机备份也不等于正式运营时不花钱。
- 每周记录：供应商账单增量（元）、审核/复查分钟、非基线自动发现并核验通过的独立活动数。现金单位成本 = 同期可归因增量费用 ÷ 该活动数，人工时间另列；分母为 0 不计算。首个周期不足 7 天，不按瞬时值推算整月或承诺永久零成本。
